# Troubleshooting

Symptoms, their cause and the fix. Error codes are the stable `code` values in
JSON error bodies; the full Live list is the
[error catalog](../reference/live-protocol.md#errors). Start with the doctor:

```sh
npx nestvexa doctor              # versions, peers, sessions, CSRF flags, secrets, manifests
npx nestvexa doctor --production # deployment gaps become failures
npx nestvexa check               # doctor plus a strict TypeScript compile
```

See [CLI reference, doctor](../reference/cli.md#doctor) for every check.

## Startup errors

| Message                                                                           | Cause and fix                                                                                                                                                                                      |
| --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Integrated Live requires CSRF and authorized actions`                            | `security.csrf` or `security.requireAuthorizedActions` was turned off while Live is enabled. Both must stay on ([configuration](../reference/configuration.md)).                                   |
| `live.enabled must match the explicit umbrella Live registration.`                | `live: { enabled: true }` in the options needs the second `NestvexaModule.forRoot` argument (components and policies), and the reverse.                                                            |
| `This distribution requires the hbs engine. Register another adapter explicitly.` | The `nestvexa` umbrella renders with Handlebars. For EJS, Pug or Nunjucks, register the adapter (`npx nestvexa add engine ejs`, [template engines](../guides/template-engines.md)).                |
| `Fastify reply.view is already registered. Configure a single view owner.`        | Another plugin (for example `@fastify/view`) owns `reply.view`. Remove it; `configureNestvexa(app)` installs the decorator ([Fastify host](../../examples/fastify-host/README.md#platform-notes)). |
| `configureNestvexa options are accepted on the first call only`                   | `configureNestvexa(app, options)` was called twice with different options. Call it once, before `app.listen()`.                                                                                    |
| `Nestvexa Alpine supports stable Alpine 3.17.x only`                              | A host-supplied Alpine of another version was passed to the bridge. Use the bundled Alpine CSP build (automatic mode) or Alpine 3.17.x ([Alpine bridge](../../packages/alpine/README.md)).         |
| `ERR_REQUIRE_ESM` in a CommonJS Nest app                                          | The packages are ESM. CommonJS hosts load them through `require(esm)`, which needs Node 22.12 or later ([output format](../architecture/package-dependency-graph.md#output-format)).               |

## Live action responses

| Status and code                                            | Cause and fix                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `401 IDENTITY_REQUIRED` (or your own `401`)                | Your `resolveIdentity` returned no valid identity or threw, usually because the session has no CSRF token yet. Create the session token in the page route before mounting (`request.session.csrf ??= …`), and make sure the session middleware runs before Nestvexa.                                                             |
| `403 ORIGIN_REJECTED`                                      | The `Origin` header differs from the configured `origin`. Set `origin` to the exact public scheme, host and port users load the page from (projects generated by `nestvexa init` read it from `NESTVEXA_ORIGIN`); behind a proxy that is the public URL, not the internal one ([reverse proxy](../deployment/reverse-proxy.md)). |
| `403 CSRF_REJECTED`                                        | `x-nestvexa-csrf` does not match the identity's `csrfToken`. Typical causes: the session was regenerated (sign-in or sign-out) after the page rendered, or two session cookies compete. Reload the page after changing the session.                                                                                              |
| `403 ACTION_FORBIDDEN` / `COMPONENT_FORBIDDEN`             | Your `authorize(identity, component, action)` returned false. Policies are deny-by-default; list `$mount` and `$sync` as well as the action names.                                                                                                                                                                               |
| `409 STALE_REVISION`                                       | The state changed since the browser rendered it (another tab or a realtime refresh). Nothing ran; the client resyncs once and the user can retry.                                                                                                                                                                                |
| `409 COMPONENT_BUSY` / `ACTION_BUSY`                       | Another request for the same component (or, with `concurrency: 'identity'`, the same action of the identity) is still running. Retry later; declare `idempotent: true` on actions that may be safely resent.                                                                                                                     |
| `409 ASSET_VERSION_MISMATCH`                               | The page was rendered with older client assets than the server now expects. The client reloads the page unless a `nestvexa:reload` listener cancels it ([asset version](../reference/live-protocol.md#asset-version)).                                                                                                           |
| `410 INVALID_SNAPSHOT`                                     | The state reference is unknown, expired (15 minutes in the memory store), revoked or owned by another identity. After a restart or on another replica without a shared store, every snapshot is unknown: use `RedisLiveStore` or sticky sessions ([multiple replicas](../deployment/multi-replica-redis.md)).                    |
| `413 PAYLOAD_TOO_LARGE`                                    | The envelope exceeds 64 KiB, depth 16 or 5,000 nodes, or the rendered HTML exceeds 1 MiB. Keep large data on the server and paginate ([limits](../reference/live-protocol.md#limits)).                                                                                                                                           |
| `415 CONTENT_TYPE`                                         | A proxy or custom client changed the request to something other than `application/json` (UTF-8).                                                                                                                                                                                                                                 |
| `422 STATE_LOCKED` / `STATE_TYPE` / `STATE_INVALID`        | The browser tried to write a field that is not `@State({ writable: true })`, changed its JSON kind, or failed its `validate` callback.                                                                                                                                                                                           |
| `429 RATE_LIMIT`                                           | The identity exceeded `maxRequestsPerMinute` (default 60). Polling and realtime refreshes count; raise the budget for dashboards, and honour `Retry-After`.                                                                                                                                                                      |
| `503 STORE_CAPACITY`                                       | The memory store holds 1,000 component states. Use a shared store for real traffic.                                                                                                                                                                                                                                              |
| `503 STORE_UNAVAILABLE`                                    | The shared store (Redis) is unreachable or its circuit breaker is open; stored state is kept and the client retries later ([resilience](../guides/resilience.md)).                                                                                                                                                               |
| `504 ACTION_TIMEOUT` / `HOOK_TIMEOUT` / `COMPUTED_TIMEOUT` | An action, lifecycle hook or async `@Computed` exceeded its deadline (`timeoutMs`).                                                                                                                                                                                                                                              |

Uploads (`@nestvexa/uploads`) and realtime (`@nestvexa/realtime`) use their own
codes, for example `TYPE_NOT_ALLOWED`, `CONTENT_MISMATCH`, `FILE_TOO_LARGE`,
`UPLOAD_EXPIRED` and `CHANNEL_FORBIDDEN`; see the [uploads guide](../guides/uploads.md)
and the [realtime guide](../guides/realtime.md).

## Browser problems

- **Nothing reacts to clicks.** The page has no `{{nvScripts}}` in its layout,
  or `await configureNestvexa(app)` was not called before `app.listen()`, so the
  boot module and client assets are not served. Check the network panel for the
  boot script under `/_nestvexa/` ([default setup](../guides/default-live-setup.md#document-scripts)).
- **CSP blocks the boot script.** With a nonce-based policy, render
  `{{nvScripts nonce=cspNonce}}` with a fresh per-request nonce; with
  `'strict-dynamic'` a nonce is required ([nonces](../deployment/csp-and-headers.md#nonces-with-nvscripts)).
- **Trusted Types violation and a suspended component.** Add the `nestvexa`
  policy to the `trusted-types` directive; the client fails closed instead of
  falling back to untrusted strings ([Trusted Types](../guides/csp.md#trusted-types)).
- **Alpine expressions do not run.** The bundled Alpine is the CSP build, which
  never evaluates arbitrary expressions. Move logic into `Alpine.data()`
  components ([Alpine and host code](../deployment/csp-and-headers.md#alpine-and-host-code)).
- **A component shows `data-nv-suspended`.** A network, protocol or rendering
  failure suspended it; reload the page. Forms with an explicit `action`
  attribute fall back to a native submit
  ([full-page fallback](../guides/offline.md#full-page-fallback-for-a-suspended-component)).

## Deployment

- **Several replicas.** Live state, server-action idempotency, rate limits and
  pending upload tokens are process-local by default. Use `RedisLiveStore` and
  the Redis realtime broker from `@nestvexa/realtime-redis`, and sticky sessions
  for uploads ([multiple replicas](../deployment/multi-replica-redis.md)).
- **Redis Cluster.** Not supported: a commit spans keys in different hash slots.
  Use a single Redis primary (standalone or Sentinel-managed).
- **Fastify.** No extra view plugin is needed; Live requests use Fastify's
  built-in JSON parser. `nestvexa init` adds `@fastify/cookie` and `@fastify/session`, and
  generated policies read `request.session.sessionId` instead of `request.sessionID` ([CLI, Express and Fastify](../reference/cli.md#express-and-fastify)).

## Working on this repository

- **`pnpm docs:build` fails with "packages/cli is not built" or "missing; run
  `pnpm build`".** The docs build reads the built CLI and package declarations:
  run `pnpm build` first.
- **Tests import `dist`.** Build the package and its dependencies before running
  its tests: `pnpm --filter @nestvexa/cache... build`.
- **Port already in use.** Every example reads `PORT`; the defaults are listed in
  the root [README](../../README.md#runnable-examples) and
  [ports](../contributing/ports.md).
