# Directive combination matrix

This page maps each `nv:*` directive, its modifiers and its supported combinations to the tests that prove them. Three layers are used:

- **Grammar** — [client-directive-grammar.test.ts](../../tests/client-directive-grammar.test.ts): oracle-checked parser tables (Node).
- **Chromium** — [client-directive-combinations.test.ts](../../tests/client-directive-combinations.test.ts) and [client-runtime-resilience.test.ts](../../tests/client-runtime-resilience.test.ts): the canonical bundled client in real Chromium with a deterministic in-page Live server ([harness](../../tests/support/live-matrix.ts)) and real Playwright input.
- **Browsers** — [directive-lab.spec.ts](../../tests/browser/directive-lab.spec.ts): a real Nest server ([example](../../examples/directive-lab/README.md)) in Chromium, Firefox and WebKit.

Earlier focused suites (events, models, loading, presentation, observers, sort, stream, upload, confirmation, focus, lifecycle) remain the detailed evidence for each slice; this matrix adds the cross-directive combinations.

## Runtime edge cases

| Area            | Proven behavior                                                                                                                                                                                                                                                                              |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Focus/selection | caret and backward selection in an unbound input, textarea selection with a newer bound draft, focus moved to the root when the focused control is removed (temporary `tabindex` released), keyed node keeps focus when moved, user focus during a pending request is never stolen           |
| Scroll          | component scroll container and window scroll retained across morphs                                                                                                                                                                                                                          |
| Native state    | unbound select/checkbox and `contenteditable` content stay local                                                                                                                                                                                                                             |
| Accessibility   | live regions updated in place (same node), `aria-busy`/status visibility, reduced motion, axe scan of the lab in three browsers                                                                                                                                                              |
| Error recovery  | 500 suspends without an offline hint, 422 stays usable, dropped connection shows the hint and recovers after remount, deadline/malformed/stale responses report `TIMEOUT`/`RESPONSE` and reject queued work, DOM error events expose only `{ code }`                                         |
| Memory          | page listener count identical after 300 morphs with replaced, direct and scoped listeners; Chromium `JSEventListeners`/`Nodes` stable (CDP after GC); identical listener set per mount and none left after 50 mount/dispose cycles; removing a component cancels timers and scoped listeners |
| CSP             | strict CSP with enforced Trusted Types end to end, fail-closed when the policy is not allowed, no dynamic code evaluation in the bundle — see the [CSP guide](../guides/csp.md)                                                                                                              |

## Documented gaps

- `nv:stream` HTML fragments, touch/grid/cross-list `nv:sort`, file/array/nested-path models and checkbox groups remain unsupported, as stated in their references.
- Combination rows run in Chromium; the Firefox/WebKit layer covers the directive lab flows, not every matrix row.
- Manual screen-reader verification (NVDA/VoiceOver) has not been performed; announcements are verified structurally (live region identity, ARIA state).
- An exception thrown by a server action ends that server instance (`410` on the next request), so the client treats it as uncertain and suspends; only the documented 4xx allowlist is recoverable.
