# Preliminary security design review

Date: 2026-10-27. Result: **NOT YET READY — BLOCKERS**. Scope: internal implementation checkpoint; no independent penetration test, external audit or ASVS certification occurred.

## Reviewed boundaries

The MVC path retains normal Nest routing. Template files/helpers are trusted application code; data interpolation escapes by default. Root-relative resolution and realpath containment reject traversal and escaping symlinks. Production precompilation accepts trusted build artifacts rather than client-named modules. Core config rejects unknown/accessor/prototype hazards. These controls have scoped unit/integration fixtures, not proof against every context or filesystem attacker.

Live now executes bounded JSON parsing, opaque host-bound state, expiry/revision locks, explicit action/state registries and generated Nest handlers in real Express/Fastify tests. Cookie-backed browser tests reject forged origins, absent CSRF, cross-session references and stale revisions. The stored public state excludes services. Memory storage is single-process. Failed action/render callbacks invalidate state because external effects cannot be rolled back or safely retried. Capacity remains bounded while expired/revoked callbacks are in flight. Client grammar rejects executable action expressions, checks response identity/revision and preserves explicit ownership boundaries in the tested slice. These scoped passes are not the complete release security gate.

The Alpine adapter exposes call/get/set through the host's public magic API and cleanup lifecycle. It rejects unsupported host versions or conflicting client installation and restricts coexistence to ignored subtrees. The real CSP build and fixture accessibility checks passed across Chromium, Firefox and WebKit. Full multi-framework ownership and accessibility acceptance remain open. Accessibility scanning found a real target-size issue; external sample CSS was corrected and verified without suppressing the rule.

The model synchronization route authorizes `$sync` independently of actions. It retains class/global Nest policies while intentionally excluding action-method metadata. Read access and lifecycle work must therefore be protected at component/global scope and by the host callback. Writable/type/domain validation runs before transaction entry, allowing rejected edits to recover without token loss; transaction compare-and-set still rejects stale validation winners. Scoped Express/Fastify tests cover validation rejection, detached frozen validator inputs, class/global authorization, cross-owner access and shutdown races. Browser tests cover strict casts, composition, focus and newer edits during morph. This adds evidence to the partial review without establishing full state/action coverage or independent approval.

The rendering slice keeps loading targets and replacement directives in a closed data grammar. Loading effects allow specific native/ARIA attributes and simple class tokens, restore server control baselines, and reject competing property owners. These effects are presentation state and cannot authorize server work. Explicit replacement removes local DOM ownership, cancels scheduled client work and aborts nested client requests before removal; an abort does not roll back server effects. When all original controls for a dirty field are removed, its local edit is discarded so it cannot silently reappear in a later payload. Recursive duplicate-key preflight rejects invalid owned markup before patching it. Controlled Chromium lifecycle fixtures cover these client boundaries; official framework islands, full nested server components and independent review remain open.

Wrapper-only `nv:ignore.self` preserves current attributes while leaving descendants under Live ownership. Effective incoming projection precedes preview validation and native form-owner capture, avoiding validation against wrapper attributes that will not be applied. Retained same-node `nv:*` configuration is fixed; incompatible changes reject before owned HTML is patched, and attribute/model/loading/replacement writers cannot share that wrapper. Native input/textarea/select/option/optgroup elements, editable wrappers and Live/island roots are explicitly unsupported. Normal↔self ownership transitions replace and clean up the removed subtree; whole-ignore ownership remains opaque until key/ancestor replacement. The [wrapper guide](../guides/ignore-self.md) records these boundaries. This is not a new authorization or HTML-sanitization guarantee, and `.self` does not meet the Alpine adapter's whole-ignore isolation requirement. Rejected responses or aborted requests may follow already-committed server effects, so no automatic retry or rollback safety is inferred. Current test evidence remains scoped to recorded runs, not complete renderer/security acceptance.

## Findings and release blockers

The native-control slice snapshots owned controls before DOM mutation and keeps unbound drafts out of Live state and payloads. Changed server defaults remain authoritative; replacement, model-binding, cast and input-type changes clear incompatible hidden drafts. File selection retention is browser behavior, not an upload implementation. Native radio groups must use unique names or distinct forms across owners; shared cross-owner groups are not a proven isolation boundary. Seven raw component marker attributes detect external browser lifecycle changes and release pending work, but do not authenticate markup or replace server owner/CSRF/revision checks. An aborted request may already have committed server effects; reconcile authoritative state before explicit remount and never infer rollback or retry safety. The current checkpoint adds 39 native-control and 25 ownership Chromium fixtures plus 15 actual Nest browser cases across three engines; full renderer, transport and security acceptance remains open.

## Dependency and distribution history

The dependency audit found a high Multer advisory in the Nest Express tree; upstream fixes it in 2.5.0. Workspace and external-consumer overrides were added and a clean audit rerun reported. The new npm/pnpm checker initially failed on missing workspace links for Alpine; the subsequent seven-package run passed both external strict-TypeScript and real MVC/Live consumers, with zero exits for install, compile, HTTP smoke and Node package imports. Its report timestamp is `2026-10-26T11:07:39.375Z`. Preserve initial failures and successful scoped reruns. Repository overrides do not automatically protect downstream apps, and later edits still require repacking.

## Review limitations and next evidence

No production secrets or real customer data are needed for the fixtures. Credentials must not appear in logs, tarballs or diagnostics. Host operators own authentication/session infrastructure, TLS/proxy policy and deployment hardening; a framework boolean cannot install those guarantees. Before release, conduct an independent review of the [threat model](threat-model.md), [ASVS mapping](asvs-traceability.md), complete attack corpus and immutable build/test/package reports. The current review author is an internal coding-agent role; no human reviewer identity is invented.
