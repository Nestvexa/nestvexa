## Contracts checked before implementation

- **Nest MVC:** retain controller `@Render` and configure its HTTP adapter using public APIs. Express and Fastify configure views differently. [Official MVC documentation](https://docs.nestjs.com/techniques/mvc).
- **Nest scopes and execution:** request providers have request lifetime; arbitrary method invocation is not a Nest route pipeline. Metadata presence cannot establish guards, pipes, interceptors or filters execution. Generated routes or documented public integration must be exercised with real requests. [Injection scopes](https://docs.nestjs.com/fundamentals/injection-scopes), [execution context](https://docs.nestjs.com/fundamentals/execution-context).
- **Inertia v3:** initial page data belongs in an `application/json` script with `data-page` matching the root ID. The protocol requires escaping every forward slash in script JSON and prohibits HTML entity encoding there. JSON visits set `X-Inertia` and `Vary`; redirect/location conflict behavior is explicit. Official-client integration, props metadata and installed package versions are still unimplemented/unverified. [Canonical protocol](https://inertiajs.com/docs/v3/core-concepts/the-protocol).
- **Livewire 4:** documentation exists for the stated version and provides behavior inspiration only; Nestvexa is not wire-compatible and does not copy its implementation. [Quickstart](https://livewire.laravel.com/docs/4.x/quickstart).
- **Alpine:** the ordinary distribution uses expression evaluation incompatible with a policy forbidding unsafe-eval. The separate CSP distribution supports a constrained expression language. The example runs `@alpinejs/csp` 3.17.5 with explicit `installLiveAlpine` before host startup. Recorded three-browser fixture checks include Alpine interactions under a CSP without unsafe-eval; full lifecycle acceptance remains open. [Official CSP guide](https://alpinejs.dev/advanced/csp), [extension lifecycle](https://alpinejs.dev/advanced/extending).
- **Vite:** current documentation describes separate development and build paths, backend integration and SSR. Its documented Node minimum is 20.19+/22.12+; Nestvexa targets maintained LTS releases instead of treating the minimum as support policy. Exact Vite/framework plugin selection is deferred until optional adapter implementation. [Vite guide](https://vite.dev/guide/).
- **Security:** OWASP identifies ASVS **5.0.0**, published 2025-05-30, as the stable standard. A requirement-by-requirement mapping and independent security review remain release blockers. [ASVS](https://asvs.owasp.org/).

## Wrapper-only ignore reconciliation

The [Livewire 4 ignore documentation](https://livewire.laravel.com/docs/4.x/wire-ignore), rechecked **2026-10-27**, distinguishes retaining a whole subtree from retaining only an element's attributes while children remain updateable. This is behavior inspiration for Nestvexa's original `nv:ignore.self` implementation, not protocol or source compatibility. Nestvexa independently restricts native/editable/renderer-root placements, competing same-node writers and retained directive reconfiguration; see the [guide](../guides/ignore-self.md).

The new client projects retained wrapper attributes into effective incoming markup before preview validation and native form-owner capture. Ordinary↔self ownership changes replace the wrapper; existing whole-ignore nodes remain opaque until key/ancestor replacement. Attribute ownership adds no server authorization guarantee and does not satisfy Alpine's whole-ignore `$live` isolation requirement. No dependency or supported version range changed.

## Bounded browser transport

The later transport slice changes no dependency selection or supported version range. It uses Fetch/ReadableStream body consumption, browser timers and AbortController with a dispatch-to-body deadline; queue wait is excluded. The byte accumulator starts at 16KiB, grows geometrically up to2MiB and accepts complete UTF-8/JSON only after the byte limit is respected. The [Fetch body contract](https://fetch.spec.whatwg.org/#concept-body-consume-body) and [reader cancellation contract](https://streams.spec.whatwg.org/#rs-reader-cancel) were rechecked October 27. Deadline, error classification, suspension and explicit-recovery semantics are Nestvexa policy rather than platform guarantees; see the [guide](../guides/request-lifecycle.md).
