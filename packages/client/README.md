# @nestvexa/client

Post-morph [focus restoration](../../docs/guides/focus-restoration.md) falls back to an available component root when a focused control becomes unavailable, preserves host-selected focus, and releases its temporary tabindex/listener on blur, release or disposal. Existing root focus policy stays host-owned; complete keyboard/screen-reader acceptance remains open.

Small experimental browser-only Live client. Import `createLiveClient` and explicitly call `mount()`; `dispose()` removes listeners, observers and aborts in-flight requests. Imports do not touch DOM globals. No Nest or frontend framework dependencies are included.

```js
import { createLiveClient } from '@nestvexa/client';
const client = createLiveClient({
  requestTimeoutMs: 30_000,
  onError(error) {
    console.error(error.message);
  },
});
client.mount();
```

Install local packed artifacts while unpublished. Future npm/pnpm/yarn package name is `@nestvexa/client`. ESM output requires modern browsers with fetch, ReadableStream, TextDecoder, AbortController, crypto.randomUUID and MutationObserver. The local matrix includes Chromium, Firefox and WebKit; consult the latest report for pass/fail outcomes.

Implemented directives: click, submit, keydown, model, loading/target, replace, ignore, text, show, bind, dirty, cloak and ref. Event modifiers support prevent/stop/self/once, keyboard/system filters, debounce and leading throttle; see the [exact grammar](../../docs/reference/directives.md). Unsupported modifiers/directives are rejected explicitly. Expressions are not evaluated. The optional [Alpine adapter](../alpine/README.md) supplies `$live.call/get/set` inside an ignored ownership boundary. The full master directive matrix remains unmet.

`nv:ignore.self=""` retains an inner wrapper's current attributes while its children remain Live-owned. Classes, style, ARIA and IDs stay with the wrapper; use a stable `data-nv-key` if a widget changes its ID. Same-node `nv:*` configuration is fixed across retained updates: change the key or replace an ancestor to reconfigure it. Attribute/model/loading/replacement effects must target children instead. Native input/textarea/select/option/optgroup elements, editable wrappers and Live/island roots explicitly reject `.self`. Ordinary↔self ownership changes replace the wrapper and clean up removed children; an existing whole-ignore subtree remains opaque until key/ancestor replacement. Effective incoming attributes are projected before preview validation and native form-owner reconciliation. `.self` does not grant Alpine `$live` isolation or framework ownership of its children. See the [wrapper ownership guide](../../docs/guides/ignore-self.md) for exact restrictions and failure behavior.

`nv:model` defaults to deferred local edits sent with the next action. `.live` synchronizes after a trailing 150ms debounce; `.blur` waits for focusout, and `.change`/`.lazy` wait for native change. Explicit `.debounce.300ms` and `.throttle.500ms` imply live mode; bare timers use 250ms, with whole-number intervals from 1 to 60,000ms. Throttle sends on the leading edge without a trailing call. A mode cannot combine blur/change/defer with a timer. `.number` accepts complete finite decimals; `.boolean` accepts only true/false/1/0 values. Conflicting, duplicate and unknown modifiers are rejected.

Models support text-like, number, checkbox and radio inputs, textareas and single selects. Unchecked radios emit no update; checkboxes produce booleans. Empty numeric controls are invalid. Multiple selects, file/array models and nested paths are unsupported. IME composition waits for the final input. Invalid conversions block component requests until corrected or the invalid control is removed. Timers are canceled on ownership/configuration changes, removal and disposal; an ordinary action also cancels pending model timers. Models use the protected internal `_sync` endpoint, requiring explicit host `$sync` authorization and writable server state. Method-specific action guards do not govern synchronization: use component/global guards or the host policy for every-write authorization.

Native reset buttons and `HTMLFormElement.reset()` reconcile owned model drafts with the resulting control values, clear validly reset local conversion/composition state and cancel affected field model timers. Reset does not send an action or `_sync`; it records newer field versions so a pending response cannot restore a discarded edit. Canceled resets leave drafts and timers unchanged. Reconciliation uses actual form ownership, including disabled and externally associated owned controls, while respecting ignored/island/client boundaries. Invalid numeric defaults, unselected model-radio defaults, conflicting field aliases and cross-owner radio groups cancel the reset with an explicit error. Synthetic `dispatchEvent('reset')` does not execute native reset and is ignored. See the [native reset guide](../../docs/guides/form-reset.md) for timing, alias behavior, stale-plan cleanup and unsupported states. This does not implement the complete forms package or change server authorization.

Loading presentation tracks queued and executing requests per action. `nv:loading=""` shows pending content; `.remove` hides it while pending. `.class="working"` and `.attr="disabled"` apply reversible effects; adding `.remove` removes the named class/attribute while pending. `nv:target="save,$sync"` limits an effect to matching requests; without a target, any pending action or synchronization activates it. The grammar allows up to 16 unique simple class tokens or action targets, and only `disabled`, `readonly`, `aria-disabled`, `aria-busy` attributes. Captured class/attribute values are restored, so a server-disabled control remains disabled after completion. Delays and arbitrary attributes/classes are not supported. Conflicting property owners, root visibility and root `aria-busy` loading effects are rejected. These are presentation controls, not authorization.

`nv:replace=""` retains its owned inner wrapper while replacing its children; wrapper attributes still follow server markup. `nv:replace.self=""` replaces the element as well. The incoming fragment chooses the mode. A component root or an ignored/nested/island boundary cannot itself carry replacement; an explicitly replaced ancestor may remove such descendants. Native controls and void elements require `.self`. Replacement resets native/file selections and local Alpine/widget state; it deliberately discards local edits when all original controls for that field are removed. Normal keyed morphing retains ownership boundaries.

A component root has one active client owner. A second client cannot attach competing listeners; dispose the owner before transferring it. The client records the raw values of seven server-created marker attributes: component ID, name, endpoint, CSRF token, snapshot, revision and public state. External changes invalidate that registration once, abort its work and require explicit disposal/remounting after the host reconciles it. Its own successful response writes remain valid. This is browser consistency checking, not a signature or authorization mechanism. Server identity, CSRF, ownership and revision checks remain necessary. Moving a root under an island releases ownership without claiming that DOM removal occurred; putting `nv:ignore` on a Live root is invalid. Independent Live roots under an ignored ancestor remain separate registrations.

`client.call(element, action)` returns the queued request promise. `get(element, field)` returns detached state or local edits. `set(element, field, primitive)` updates local state until submitted. `refs(element)` resolves owned references from the current DOM. Server authorization and writable-state checks always apply.

Requests are serialized per component, capped at 16 pending operations, sent same-origin with host CSRF token, and never automatically retried. Duplicate submits are suppressed. Response identity/request/revision checks precede DOM updates. Keyed nodes retain identity unless incoming markup explicitly replaces them; nested live/ignored/island roots are ownership boundaries. Focus/caret and newer input edits are preserved where tested; removing the focused control moves focus to the retained component root.

`requestTimeoutMs` accepts an integer from 1 through 300,000; the default is 30,000ms. Each deadline starts when its request is dispatched and covers fetch plus body consumption, excluding time in the component queue. The client counts the response body's bytes as they arrive, rejecting more than 2,097,152 bytes before decoding the complete text. It requires `application/json` (parameters allowed) and valid UTF-8. A declared length cannot bypass the streaming limit. This deadline does not cancel server business work or preempt synchronous JavaScript.

An uncertain network, deadline, response/protocol or rendering failure suspends further transport for that component and its nested owned roots. The registration, local drafts and `get`/`set` access remain available; enhanced form submission remains prevented. Pending requests are aborted, queued calls reject the stored cause, loading baselines restore and component `aria-busy` becomes false. Independent sibling components remain separate. Errors use stable `LiveClientError` codes including `NETWORK`, `TIMEOUT`, `RESPONSE` and `HTTP`; exported `LiveHttpError` adds a numeric `status`. Native fetch exception text and HTTP error bodies are not exposed by the transport. The HTTP rejection allowlist permits explicit correction after 400/401/403/404/405/413/415/422/429; it never triggers an automatic retry or guarantees a business rollback. Other HTTP outcomes suspend transport.

Recover by reloading or obtaining trusted authoritative server state, then disposing and explicitly mounting against reconciled markup. Simply clearing the browser failure or reusing old markers cannot prove that a timed-out action did not commit. Removal/disposal cancellation settles affected `call()` promises without applying a late response; a resolved cancellation is not a business-success acknowledgement. See the [request lifecycle guide](../../docs/guides/request-lifecycle.md) for recovery, errors and exact bounds. Full transport/fault/platform acceptance remains open.

Ordinary morphing merges native values with incoming server defaults. Unbound text/textarea edits, checkbox/radio choices and single/multiple-select selections remain local while their server defaults stay unchanged; a changed default is authoritative. These unbound values are not added to Live state or request updates. Textarea reset defaults are updated, option keys preserve duplicate-value identity, and file selections survive ordinary reconciliation without implying upload support. Compatible newer model drafts survive only while an original matching field/cast/control type remains; changes clear hidden stale edits. Multiple selects remain unsupported as `nv:model` array values. Editable content stays local while `contenteditable=false` content follows the server. Explicit replacement intentionally resets local state. Use valid forms and unique radio names or distinct forms per component; shared native radio groups across owners are not a proven isolation boundary. See the [native control and ownership guide](../../docs/guides/native-controls.md) for rules, reset options and limits. The full native-input/teleport/framework lifecycle matrix remains open.

Render only trusted application templates. The client rejects active document tags, non-HTML namespaces and inline event handlers in updates; this is defense in depth, not a general HTML sanitizer. Use server escaping and a restrictive CSP. Errors go to `onError` or `nestvexa:error`. Bubbling, noncancelable `nestvexa:before-remove` and `nestvexa:after-insert` events identify each outer removed/inserted element subtree; descendants are included rather than notified individually. Retained keyed moves emit neither event. Removal cancels client timers/listeners and aborts nested Live requests before releasing ownership. `nestvexa:updated` follows Live reconciliation/discovery; asynchronous third-party initialization remains the host's responsibility. Framework island adapters and the full nested-server API remain unimplemented.
