# Live counter

Run `pnpm build`, then `pnpm --filter @nestvexa/example-live-counter start`. Visit `http://127.0.0.1:3101`.

This real Nest/Express server uses `express-session`, per-session CSRF tokens, exact-origin checks, server-side component state, method allowlists, and monotonic revisions. It demonstrates click actions, deferred and independently synchronized model updates, form submission, loading state, focus preservation, and an ignored local widget under a CSP without unsafe-eval.

The sample registers `NestvexaAssetsModule` from `nestvexa/assets` once. Its application-owned `/assets/boot.js` response reads `NestvexaAssetsService.getManifest()` and imports `entries.live`, `entries.alpine` and `entries.alpineAdapter`. This replaces the previous 15 per-file asset handlers. Versioned asset responses use immutable caching; the boot response uses `Cache-Control: no-store` so a new process snapshot supplies current imports. CSS and boot behavior remain application-owned. See the [asset guide](../../docs/guides/client-assets.md) for prefix configuration, conditional requests, deployment limits and migration.

Asset registration performs no browser startup or Live security setup. This example still owns `LiveModule.register()`, session/identity resolution, authorization, renderer initialization/disposal, local `Alpine.data()` definitions and `Alpine.start()`. The umbrella's automatic `live.enabled: true` setup and CLI initialization remain unmet. The snapshot includes the original CSP build and its retained license comments; see [third-party notices](../../THIRD_PARTY_NOTICES.md). Browser/package outcomes must be read from the implementation checkpoint rather than inferred from this example description.

The display name uses default deferred `nv:model` and is sent with the save action. The model section adds a live search with a 100ms trailing debounce, a nickname synchronized on blur, a quantity converted to a number on change, a boolean select and a radio group. Outputs show the server-rendered value. Search has a pure writable-state validator limiting it to 30 characters; rejection leaves the snapshot/revision available for a corrected update. Invalid local numeric input blocks requests until corrected. See the [model reference](../../docs/reference/directives.md) for defaults, timing/cast rules, IME behavior and unsupported inputs.

“Reset display draft” and “Reset model drafts” are native reset buttons. They reconcile the owned local model values with current defaults and cancel affected model timers without calling an action or `_sync`. A reset made during a pending action remains a newer local version; a later save sends that reset value. Canceled resets keep the edit and its timer. The [reset browser scenarios](../../tests/browser/form-reset.spec.ts) exercise these flows against the actual Nest sample; consult the checkpoint for executed outcomes. The [guide](../../docs/guides/form-reset.md) explains invalid defaults, field aliases, external form associations and why synthetic reset events are not native resets.

The sample explicitly permits `$sync` in `authorize` for the generated `POST /_nestvexa/live/counter/_sync` endpoint. Synchronization still checks session identity, CSRF, origin, ownership, writable state and revision. It runs component/global Nest policies without selecting an action method, so action-method guards do not protect model writes. Production must put every-write authorization in `authorize` or component/global guards. Synchronization does not call `save` or other actions and does not execute action hooks.

The sample includes the actual Alpine CSP build and an isolated local widget using `$live.call/get/set`. Its local count survives Live updates. Text/attribute/visibility/dirty/cloak/ref bindings also have browser tests. The [model scenarios](../../tests/browser/models.spec.ts) exercise the synchronization controls and error recovery; the implementation checkpoint records executed validation. The full directive matrix remains incomplete.

The slow-action button uses `nv:loading.attr="disabled"` with `nv:target="slow"`. Nearby controls demonstrate a targeted class, inverse loading visibility and a server-disabled button whose disabled baseline must survive completion. Loading includes queued requests and accepts `$sync` as a target for model synchronization; these presentation effects do not grant authorization or prevent forged requests.

The replacement panels demonstrate `nv:replace=""` for children and `.self` for the whole element. Every successful update resets the temporary note and the Alpine widget inside a replaced ancestor, while the ordinary ignored Alpine widget outside those panels retains its state. Replacement is deliberate state loss: do not put drafts or selected files inside it when they must survive updates. Removed subtrees emit `nestvexa:before-remove`, inserted subtrees emit `nestvexa:after-insert`, and `nestvexa:updated` follows Live reconciliation/discovery. The [loading/replacement browser scenarios](../../tests/browser/replacement-loading.spec.ts) exercise the sample; consult the checkpoint for executed results rather than assuming complete teardown/accessibility coverage.

The “Widget wrapper with live children” section uses `nv:ignore.self=""`. Widget-managed wrapper attributes remain local while its increment/save actions, model, text, loading indicator and nested whole-ignore note retain their separate ownership rules. “Toggle detail” switches this wrapper between self-owned and ordinary modes, deliberately replacing it and resetting removed local state. The [wrapper browser scenarios](../../tests/browser/ignore-self.spec.ts) exercise retained class/ARIA attributes, escaped model text, newer pending edits, focus/loading and those transitions. See the [guide](../../docs/guides/ignore-self.md) for frozen same-node directive configuration, unsupported native/editable/root placements and the stable-key rule for widget-managed IDs. The isolated Alpine widget still requires whole ignore; self-ignore does not isolate its children.

The session is an anonymous demonstration identity, not a login system. Production must use a persistent host session store, stable secret rotation, HTTPS secure cookies, authenticated principal/tenant binding, distributed state and policy review. Memory sessions/state do not survive restart or coordinate replicas. Do not use this sample for irreversible business operations. Advanced directives, no-JavaScript mutation fallback and the complete forms package remain unmet.
